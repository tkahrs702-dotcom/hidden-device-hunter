# 2026-10-28 session 01YKZUS1: Bluetooth scan, mode switch, tick boxes, reviewer fixes

**What happened**
- C5 now scans Bluetooth LE as well as Wi-Fi, with a Wi-Fi / Bluetooth / Both switch (default Wi-Fi only; BOOT hold 3 s+ or the page buttons change it). BLE devices show in the same list.
- Phone page over Bluetooth (`tools/finder/finder.html`, Web Bluetooth, Chrome on Android, not Brave): auto-reconnect, tick boxes to check off devices, mode and volume buttons. The R4 page got the same tick boxes and mode buttons.
- Link pins back to D7 = RX, D6 = TX (`LINK_CROSSED = false`); the crossed setting gave no data.
- Fixed my own regression (C5 sent the device list to the phone only, so the R4 page was empty). A separate reviewer then found more: lock state lost on the R4 page, a phone connecting made the R4 redo its lock, unescaped names, double attach. All fixed.
- PR #17 merged to main. Both boards were flashed from it (C5 needed BOOT held, R4 needed double-tap RESET and its own port).

**Lessons**
- Every code review is done by a separate reviewer agent, never self-review (Taelor's rule).
- Tell Taelor what changes and why before changing it; one project at a time; one plain command per message, no quote characters.
- Seat the USB cable fully before blaming the board; an empty `$(...)` port gives "accepts at most 1 arg".
- Chrome only allows Web Bluetooth from https or a local file. The artifact frame and Brave do not work.
