# 2026-10-18 Phase 2 sniffer on the XIAO ESP32-C5
Taelor asked whether the ESP32-C5 firmware was ready and can be flashed. Nothing C5-specific existed, so `firmware/phase2-xiao-sniffer` now
builds for the C5 as well as the S3/C3 (one sketch, chip picked at compile time):
- BOOT button pin per chip (C5 GPIO28, C3 GPIO9, S3 GPIO0). D6/D7 UART pins are the same XIAO pins on every board.
- On the C5 (`SOC_WIFI_SUPPORT_5G`): country set to US, band mode 2.4 + 5 GHz, hop list adds 5 GHz channels 36-165 (DFS included,
  receive only). Channels the radio refuses are reported once and skipped.
- Device list prints 3-digit channels.
Compiled in a cloud session with arduino-cli 1.3.1 + esp32 3.3.12: XIAO_ESP32C5 31% flash, XIAO_ESP32C3 74%, no sketch warnings with
`--warnings all`. S3 not recompiled (no S3-only code changed). NOT run on hardware yet; R4 display sketch unchanged (it ignores the channel).
To flash: `arduino-cli compile --upload -p <port> --fqbn esp32:esp32:XIAO_ESP32C5:CDCOnBoot=cdc firmware/phase2-xiao-sniffer` (find the port by
serial number with `arduino-cli board list`). It enumerates as Espressif USB JTAG/serial 303a:1001, the same ID as other
ESP32 boards (SENTINEL P4 included), so confirm with `esptool chip_id` before uploading if more than one could be plugged in.

## Flashed on hardware (HaLjr, 2026-10-18 evening)
- Board on /dev/ttyACM0, confirmed ESP32-C5 with esptool (base MAC 10:bd:a3:c7:f8:60). Flash written and verified.
- First flash used the plain FQBN: the board ran but USB serial was silent. The XIAO_ESP32C5 board defaults to "USB CDC On Boot: Disabled",
  so `Serial` went to the UART pins. Reflashed with `--fqbn esp32:esp32:XIAO_ESP32C5:CDCOnBoot=cdc`; the console works.
- Boot banner: "Listening on 36 channels, 2.4 + 5 GHz (one sweep about 8 s)", maker list 771 entries, no refused-channel warnings.
  After 20 s `l` listed a device on 5 GHz ch 36 (-77 dBm) and an AP on ch 2. Commands `h` and `l` respond.
- Not yet tested: lock mode, BOOT button, UART link to the R4 display.
